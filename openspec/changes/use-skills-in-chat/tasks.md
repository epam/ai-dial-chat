## 8. Drop the tooltip workaround — the upgraded ui-kit (0.14.0-dev.46) supports the behavior natively

The kit upgrade fixes both defects the workaround existed for (verified in the installed source): `InteractiveTooltip`'s `onOpenChange`-without-`open` trap (the callback now augments the internal open state instead of replacing its setter, `onOpenChange ?? setInternalOpen`), and the instant close on leaving the row-or-panel pair (`useHover` now closes through `safePolygon()`, and `useSubMenuFloating` got the same fix so the parent Add-menu submenu no longer unmounts the tooltip panel either). Both favorites panels move to the kit's uncontrolled behavior. The lazy description fetch and its `onItemTooltipOpen` callback **stay** — that cleanup belongs to follow-up 2 (DIAL Core `description` in the listing), which has not shipped.

- [x] 8.1 `libs/skills` `FavoriteSkillsPanel`: drop the panel-controlled open state and the 300 ms grace-close machinery — `TOOLTIP_CLOSE_DELAY_MS`, `openTooltipId` state, `cancelTooltipClose`/`handleTooltipOpen`/`scheduleTooltipClose`, the close-timeout ref and its unmount cleanup, the row's `onMouseEnter`/`onMouseLeave`/`onFocus`/`onBlur` handlers, the content div's hover/focus handlers, and the `open` prop — leaving an uncontrolled `InteractiveTooltip` (`asChild`, `contentClassName="max-w-[550px]"`, kit-default Right placement) that opens on hover/focus and stays open while the pointer crosses onto the panel
