## Why

Skills are already a first-class catalog entity — authoring, favorites, sharing, archive import — but there is no way to actually use one in a conversation: the skill details panel offers no "Use in chat", and the conversation input's Add menu has no Skills entry. The backend contract for sending skills with completions is not designed yet, so this change builds the entire frontend selection UX (catalog button, input menu, favorites panel, browse modal, selected-skill display) behind a deployment-controlled kill switch, ready to be pointed at the backend contract once it exists.

## What Changes

- **Feature flag `SKILL_USAGE_ENABLED`** — new boolean env var validated at boot (`apps/chat-api/src/config/environment.config.ts`), exposed to the frontend as the client-visible `features.skillUsageEnabled` config-registry entry (mirroring how `RESPONSES_API_ENABLED` becomes `features.responsesApiEnabled`, except client-visible because it gates UI). Every piece of skill-usage UI below renders only when the flag is true. Documented in `.env.template` and `apps/chat-api/README.md`.
- **"Use in chat" on the skill details panel** (`libs/catalog` `DetailsPanel`/`Header`) — for `CatalogEntityType.Skill`, the header gains the "Use in chat" primary action (displacing Download, which returns to the Manage menu). Clicking it navigates to the chat route and attaches the skill to the conversation input, mirroring the prompt flow (router state, one-shot). **Deferred condition, documented in specs/design:** the button should eventually render only when the default model supports skills — the backend exposes no way to know that yet, so it is shown unconditionally (within the flag) for now.
- **"Skills" item in the conversation input Add menu** — new menu item (icon `IconBlocks`) rendered only under the flag, using the same nested-flyout (desktop) / stacked-bottom-sheet (mobile) chrome the Prompts item gets. Its panel contains: "My Collection" header, the user's favorite skills, a separator, and a "Browse" button; with no favorites it shows "Star a skill to pin it here".
- **Interactive tooltip on favorite-skill rows + chat-route skill details side panel** — each favorite row is wrapped in the ui-kit's `InteractiveTooltip` (shipped in 0.14): a panel anchored to the row (Right placement, 600px max width on desktop) that stays open while the pointer moves onto it, showing the skill's description above a link-style "View details" button (`IconEye` on its inline-start). Descriptions are not in the listing response Core sends today, so they are lazy-fetched: the first open of a row's tooltip (hover or focus) triggers one `SKILL.md` download + manifest parse, cached per session; until resolved — or when a manifest has no description — the panel shows the button alone. "View details" opens the catalog's skill details side panel on the chat route, composed from `DetailsPanel` newly exported by `libs/catalog`, with favorite toggle and "Use in chat" wired; on touch-only devices the tooltip renders nothing (rows still select on tap).
- **"Use skill" browse popup** — "Browse" opens the standard catalog picker shell (`CatalogView` in selector mode) restricted to the Skills tab only, mirroring the "Use prompt" modal.
- **Selected skill in the input** — a skill picked from favorites or from the browse popup becomes the single selected skill, rendered in the conversation input as a chip in the accent-active control color, dismissible from the input; selecting a different skill replaces it. (What a selected skill means at send time — request payload, persistence — is part two of this effort and explicitly out of scope.)
- **Refactor: reusable menu-overlay plumbing in `libs/conversation-input`** — the prompt-specific `promptsMenuOverlay`/`promptsMenuTitle`/`promptsBackLabel` props on `Input`/`ConversationInput`/`AddAttachmentButton` are generalized into a data-driven overlay-menu mechanism that any catalog-entity-type submenu can use; Prompts migrates onto it with no behavior change, Skills consumes it as the second client.
- **New `libs/skills` library** (`@epam/ai-dial-skills`) — hosts the host-agnostic skill-selection UI: the favorite-skills panel (rows wrapped in the ui-kit `InteractiveTooltip`), the `SkillDetailsSidePanel` wrapper composing `libs/catalog`'s exported `DetailsPanel`, and skill-specific models/types. App-owned wiring (contexts, i18n, navigation, the lazy description fetch) stays in `apps/chat` via a `useSkillSelectorOverlay` hook mirroring `usePromptSelectorOverlay`.

## Capabilities

### New Capabilities
- `skill-input-attachment`: Discovering, selecting, and displaying a skill from the conversation input's Add menu — the Skills menu item and flag gate, the favorites panel (rows with the interactive tooltip and lazy-fetched descriptions), the Skills-only browse modal, the single selected-skill chip rendered in the input, and the chat-route skill details side panel the tooltip's "View details" opens — plus the shared menu-overlay mechanism in `libs/conversation-input` both Prompts and Skills use.

### Modified Capabilities
- `catalog-use-in-chat`: gains a `CatalogEntityType.Skill` branch — "Use in chat" on a skill navigates to the chat route and attaches the skill to the composer via one-shot router state, without touching deployment selection; the skill details panel header offers the action (flag-gated, currently unconditional — the default-model-supports-skills condition is deferred and documented).
- `chat-input-tools-menu`: the "no `+` button when tools are the menu's only content" requirement's enumeration gains the skills overlay alongside attachments, chat settings, and prompts.
- `config-registry-and-env-provider`: the registry gains the `features.skillUsageEnabled` entry — `type='feature'`, `valueType='boolean'`, `visibility='client'`, `defaultValue=false`, `critical=false`, `envVar='SKILL_USAGE_ENABLED'`.
- `skill-details-panel`: `DetailsPanel` is exported from `@epam/ai-dial-catalog`'s index and becomes composable outside the Catalog page (the chat-route side panel is its second consumer; the details-resolution pipeline itself is unchanged).

## Impact

- **apps/chat-api**: `environment.config.ts` (`SKILL_USAGE_ENABLED`, boolean transform identical to `RESPONSES_API_ENABLED`), `config-registry.constants.ts` (new entry), `feature-key.enum.ts` (`FeatureKey.SkillUsageEnabled`), `.env.template`, `apps/chat-api/README.md` env-var table. No new endpoints.
- **libs/conversation-input**: `AddAttachmentButton`/`Input`/`ConversationInput` props change (`promptsMenuOverlay` family → generic overlay-menu config); `apps/chat` call sites updated in the same change; existing Prompt menu behavior and tests preserved.
- **libs/catalog**: `Header` — Skill gains the primary action (host-gated via `isPrimaryActionVisible`/`onUseInChat`, so the lib stays flag-agnostic). `DetailsPanel` becomes a public export of the lib's index (composed by `libs/skills`' `SkillDetailsSidePanel` for the chat-route side panel); its README gains the new export.
- **New libs/skills**: `FavoriteSkillsPanel` (rows with `InteractiveTooltip`), `SkillDetailsSidePanel`, and `FavoriteSkillItem` models; peers on `@epam/ai-dial-ui-kit`, `@epam/ai-dial-chat-shared`, and `@epam/ai-dial-catalog`. Requires `docs/architecture.md`, root/app README, and `validate:docs` updates.
- **apps/chat**: `useSkillSelectorOverlay` (mirrors `usePromptSelectorOverlay`), "Use skill" catalog modal (mirrors `PromptCatalogModal`), `CatalogView` header-rule wiring for Skill, `ConversationRoute` consumption of one-shot skill router state, new `SkillSelectorI18nKeys` + `en.json` keys (reusing `ButtonsI18nKeys` for shared labels).
- **Out of scope**: send-time semantics of selected skills (request payload, `custom_content`, persistence in conversation history) — part two; adding `description` to DIAL Core's skill metadata listing (planned upstream change — until it ships, descriptions are lazy-fetched per skill from `SKILL.md` via the existing skill-file download endpoint; when it lands, the lazy fetch and its N+1 request pattern are dropped — see Follow-ups in `design.md`); ui-kit Dropdown-native interactive tooltips (planned upstream change — when they land, the panel-controlled open + grace-close workaround in the favorites panels is dropped, along with the `InteractiveTooltip` `onOpenChange` and submenu-close defects found during this change — see Follow-ups in `design.md`); any backend skill-usage API; role-based rollout env var for the flag. The Prompts favorites rows were originally deferred to a follow-up change but were migrated onto `InteractiveTooltip` (same row-tooltip behavior as skills, description already available so no lazy fetch) within this change at the maintainer's request.
