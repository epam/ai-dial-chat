# Tasks

**Slicing strategy: vertical.** Each group after group 1 is an independently verifiable slice that runs from data access through UI. Groups 1–2 are the enabling foundation (lib surface, API wrappers); groups 3–7 each deliver a working user-facing capability behind `OverlayFeature.Prompts`; group 8 is the cross-cutting quality gate. The feature stays dark until group 8, so any slice can ship to `development-1.0` on its own.

**Per-slice verification** (run for every group before moving on):

```sh
npm exec nx lint  <project>
npm exec nx test  <project>
npm exec nx build <project>
```

`<project>` is `@epam/ai-dial-catalog`, `@epam/ai-dial-prompt-editor`, `chat-overlay`, `@epam/chat`, or `@epam/chat-api` depending on what the slice touched. Group 8 additionally runs `npm run openapi:check`.

**Note on group 9:** the change originally ended at group 8 and forbade backend edits. A follow-up round pulled three previously-documented limitations into scope (favourites, share links, marker filtering) and extracted the editor into a lib, so group 9 revises decisions made in groups 1, 4, 6, and 7. Entries in those groups that group 9 supersedes say so inline rather than being rewritten, so the history stays readable.
