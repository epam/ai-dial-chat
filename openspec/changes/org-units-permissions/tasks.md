# Tasks

Slicing strategy: **contract-first, then vertical.** Group 1 fixes the data contract (BFF, client, helpers) bottom-up so each slice is verifiable alone; Groups 2 and 3 are vertical slices through one panel type at a time. Groups are sequential (they touch the same files).

Rules for every slice (from `AGENTS.md`, `.claude/rules/docs.md`, `openspec/config.yaml`):
- Run verification through the `lean-verification` skill: the exact spec with `npm run test:file -- <path>` while working, `npm run verify:changed` once per finished slice, `npm run build:quiet` only when bundling can be affected. The change closes with exactly one `npm run verify:full`.
- Update docs in the same commit as the code that changes them (README of the touched lib or app, `docs/architecture.md`, `apps/chat-api/README.md`), then run `npm run validate:docs` and `npm run validate:specs`. Main specs under `openspec/specs/` are synced at archive (`opsx:archive`); the delta specs in this change are the contract until then.
- Touching `libs/*`: before the slice, check `AGENTS.md` "Library isolation" and `.claude/rules/libs.md`; after, confirm the lib has no `/api` path, generated-client import, app context, auth, env, flag, routing, analytics or storage knowledge. `libs/chat-api-client` is regenerated, never hand-edited.
- Extensionless relative imports, string enums, no `sm:`/`md:` prefixes (mobile-first), logical RTL classes.
- Commits are single-line conventional messages. No commit, push or PR without the user's explicit yes, and a leak check before each.
