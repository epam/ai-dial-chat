# Tasks

**Slicing strategy: vertical, risk-first inside it.** Slice 2 puts the route end to end (`not_configured`) before any
ADAS code exists, so the contract, OpenAPI and generated client are proven first. Slice 3 then proves the
riskiest part: the token-forwarding transport and the row-restriction guard against a fake ADAS HTTP server. The query
and mapping slices build on that. Each slice lands its own tests and docs.

Conventions for every task: backend files follow `apps/chat-api/AGENTS.md` (domain folder `apps/chat-api/src/usage-history/`,
no `modules/` wrapper, specs under `apps/chat-api/src/usage-history/tests/`), extensionless relative imports, string
enums under `types/`, arrow-function helpers, `/* */` for multi-line comments. ADAS is mocked at the HTTP boundary only:
a real `http.createServer` listening on `127.0.0.1:0` records requests and serves canned responses. The mapper and query
builders are never mocked in the tests that exercise them. Run exact files with `npm run test:file -- <path>`, run
`npm run verify:changed` once at the end of each slice, and run `npm run verify:full` once at the end.
