Slicing strategy: **risk-first**. The riskiest, most novel piece is the AND-combination logic in `resolveGenerationApiForDeployment` — getting the four-way truth table (flag × deployment capability) and the fail-closed failure path right — so that lands first as a pure/unit-testable slice (Section 2) before any controller-level integration test depends on it. The registry/enum/env plumbing (Section 1) is the shared contract Section 2 needs, so it lands first as a small, independently-verifiable foundation. Section 3 proves the full acceptance matrix end-to-end. Section 4 is documentation only and has no code dependency, so it is last. Each section ends with its own `nx` verification run.
