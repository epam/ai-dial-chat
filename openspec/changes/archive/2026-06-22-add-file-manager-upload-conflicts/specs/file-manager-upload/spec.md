## MODIFIED Requirements

### Requirement: Validation (`onValidateUpload`)
Called by `DialFileManager` before invoking `onUploadFiles`.

```ts
onValidateUpload: async (
  files: DialUploadFileItem[],
  existingFiles: DialFile[],
  _destinationFolder: string,
): Promise<FileUploadValidationResult>
```

- SHALL sanitize each file's `name` in-place using `sanitizeFileName` from `apps/chat/src/utils/file-name.ts` before performing any other check.
- SHALL NOT return `{ valid: false }` for name collisions. Name collisions are delegated to the ui-kit's internal `ConflictResolutionPopup`. Returning `{ valid: false }` for collisions blocks the ui-kit's conflict detection and MUST NOT be done.
- After sanitization, returns `{ valid: true }` in all cases not covered by other validation rules (size, type, etc. handled by the ui-kit separately).
- Does **not** call the BFF — purely client-side.

#### Scenario: Validation sanitizes names and does not block on collision
- **WHEN** `onValidateUpload` is called with `[{ name: 'my:notes.txt' }]` and `my_notes.txt` exists in `existingFiles`
- **THEN** `DialUploadFileItem.name` is mutated to `'my_notes.txt'`
- **AND** `onValidateUpload` returns `{ valid: true }` (not `{ valid: false }`)
- **AND** the ui-kit subsequently detects the `my_notes.txt` collision and opens the conflict popup

#### Scenario: Validation returns valid true for non-colliding files
- **WHEN** `onValidateUpload` is called with a file whose sanitized name does not match any entry in `existingFiles`
- **THEN** returns `{ valid: true }` and the ui-kit proceeds to call `onUploadFiles` directly

### Requirement: Upload files (`onUploadFiles`) with upload mode
`onUploadFiles(files: DialUploadFileItem[], destinationFolder: string)` SHALL determine the upload mode per file by checking whether `file.name` (case-insensitive) exists in the cached listing for the current folder:

- Name found in cached listing → `uploadMode: 'overwrite'`
- Name absent from cached listing → `uploadMode: 'create-only'`

Each file SHALL be uploaded via `uploadFile(bucket, path, fileContent, { signal, onProgress, uploadMode })` from `apps/chat/src/server-api/files.api.ts`, which passes `uploadMode` in the multipart request to `POST /api/v1/files`.

All other upload behaviors (concurrency `UPLOAD_CONCURRENCY = 3`, progress tracking, cache invalidation after batch settles) are unchanged.

#### Scenario: Replace — overwrite mode
- **WHEN** `onUploadFiles` is called with `{ name: 'notes.txt' }` and `notes.txt` exists in the cached listing
- **THEN** `uploadMode: 'overwrite'` is passed to `uploadFile`
- **AND** `POST /api/v1/files` is called without `If-None-Match` — DIAL Core overwrites the existing file

#### Scenario: Duplicate — create-only mode
- **WHEN** `onUploadFiles` is called with `{ name: 'notes (1).txt' }` generated by the ui-kit after the user chose Duplicate
- **AND** `notes (1).txt` does not exist in the cached listing
- **THEN** `uploadMode: 'create-only'` is passed to `uploadFile`
- **AND** `POST /api/v1/files` is called with `uploadMode: 'create-only'` → BFF sends `If-None-Match: *` to DIAL Core

#### Scenario: Fresh upload — create-only mode
- **WHEN** `onUploadFiles` is called with a file whose name is absent from the cached listing (no prior collision)
- **THEN** `uploadMode: 'create-only'` is passed to `uploadFile`
- **AND** the upload proceeds as create-only for race safety
