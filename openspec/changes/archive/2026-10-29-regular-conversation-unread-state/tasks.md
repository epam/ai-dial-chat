## Slicing strategy

Risk-first, then vertical: undo the draft, prove the storage and the list rule on the backend (the piece every other slice depends on), then the generation-time and rename behavior, then the client end to end. Conventions: `apps/chat-api/AGENTS.md` for backend work; extensionless relative imports in TypeScript; tests co-located (`tests/` folder next to the source for the domain folders used here); test names describe observable behavior. Run `npm run verify:changed` once after each completed slice and `npm run verify:full` exactly once at the end.
