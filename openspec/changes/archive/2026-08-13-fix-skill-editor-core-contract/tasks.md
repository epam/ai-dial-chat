> **Revision note:** This task list replaces an earlier draft that had the BFF explode a browser-uploaded ZIP into per-file multipart parts before forwarding to DIAL Core. Reading DIAL Core's actual Java source (`ComplexResourceController`/`EtagHeader`/`SkillHandler`/`ComplexResourceService`, `epam/ai-dial-core`) during a documentation-only revision pass showed Core never wants a ZIP for writes at all — the browser can and should send discrete multipart parts directly. It also showed the real create-only mechanism is `If-None-Match: '*'` (verified in `EtagHeader.validateIfNoneMatch`), not "omit `If-Match`" as an earlier iteration of this same design incorrectly concluded from an SDK doc-comment alone. **A `SkillsArchiveService` (ZIP extraction, encrypted-entry/symlink/compression-ratio checks) and corrected-but-now-superseded `SKILL_UPLOAD_MAX_FILES`/`SKILL_FILE_UPLOAD_MAX_BYTES`/`SKILL_UPLOAD_MAX_TOTAL_BYTES` env-var edits from that earlier pass already exist in the working tree** (`apps/chat-api/src/skills/archive/skills-archive.service.ts`, `apps/chat-api/src/skills/skills.module.ts`, `apps/chat-api/src/config/environment.config.ts`) — task 1 below explicitly deletes/replaces that code as its first step; do not treat its mere presence as "already done" for this revised design.
