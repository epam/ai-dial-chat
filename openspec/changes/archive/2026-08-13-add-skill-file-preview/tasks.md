Slicing strategy: **risk-first**, then **vertical**. The shared attachment-canvas gaps (zero-byte files, MIME inference) are fixed and regression-tested against chat first, since Skill Editor reuse depends on them and any regression there would be a chat-facing bug, not a Skill-only one. Once the shared pipeline is solid, the `AttachmentCanvasBody` extraction and the `libs/skill-editor` prop are built and verified independently (each an isolated slice), then wired together end-to-end in the Skill Editor page, widening from Markdown-only to every content type.
