Slicing strategy: **risk-first**, then vertical. Slice 1 makes every demonstrated
race fail as a test before any behaviour changes, so the fix is proven rather than
asserted. Slice 2 lands the one ownership change those tests need in a single
verifiable step. Slice 3 completes cleanup and cross-layer coverage. Slice 4
closes specs, docs and verification.

Conventions for every slice: `apps/chat-api/AGENTS.md` is the source of truth for
backend structure (thin controllers, `Logger` + `ConfigService`, validated env on
`EnvironmentVariables`, typed HTTP exceptions, specs beside their source). New
internal lifecycle states use named string enums. Relative TypeScript imports stay
extensionless. Tests use fake timers and deferred promises — never timing sleeps —
and assert cancellation, persisted contents and order, subscriber delivery,
admission, and resource release, never merely the final registry size. Nothing in
`libs/*` is touched, so no library-isolation guard applies; the fix is entirely
host-side backend behaviour.
