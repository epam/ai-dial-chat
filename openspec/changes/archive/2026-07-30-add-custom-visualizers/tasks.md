- [x] 2.2a Provide the deferred-request primitive the connector needs (owns a `requestId`, matches its `/RESPONSE`, settles on reply / timeout). Port it verbatim from `development:libs/shared/src/utils/DeferredRequest.ts` into `libs/visualizer-connector/src/lib/internal/`, dropping only the `DialLibRequest` import — **behaviour parity with `development` is the goal here, so its existing conventions are preserved deliberately**: the timeout path rejects with a **string** (`[${libName}] Request ${type} failed. Timeout ${ms}`) and the `Promise.race` timer is not cleared on reply. Both are consistent with the sibling `Task` primitive (`fail(reason: string)`) and with `send()`'s `catch (e) { if (e === 'Chat Visualizer destroyed') … }` string comparison — changing one in isolation would desynchronise the pair. Note that `Promise.race` has already subscribed to the inner promise by the time a late `reject` fires, so the uncleared timer cannot surface as an unhandled rejection; the only cost is a timer living until its deadline. A separate lib (`libs/chat-overlay`) has an independently written variant at `src/lib/internal/deferred-request.ts` that uses `Error` + `clearTimeout`; it is NOT the model for this port. Do NOT import across libs from `chat-overlay`'s `internal/` path, and do not refactor `chat-overlay` as part of this change. Record as a known follow-up: converge both primitives (and `Task`) on `Error`-based rejection in `chat-shared`, as one coordinated change rather than a partial migration
- [x] 2.3 Set the default iframe capability grant (design D6): `sandbox` tokens `allow-same-origin allow-scripts allow-modals allow-forms allow-downloads allow-popups allow-presentation`, and an `allow` attribute of `clipboard-write; fullscreen; accelerometer; gyroscope; autoplay; web-share; encrypted-media`. `allow-top-navigation` MUST NOT be granted. The sandbox value is hardcoded in `initIframe()` and is not overridable via constructor options
- [x] 2.3a Unit-test the capability grant: default tokens present, `allow-top-navigation` absent, `allow` attribute set
- [x] 2.4 Enforce source check on every inbound `message` event: drop when `event.source !== iframe.contentWindow`
- [x] 2.5 Leave `.ready()` **unbounded** (settles only on `READY_TO_INTERACT` or `destroy()`) — do NOT add a handshake timeout (design D7). Apply `options.requestTimeout` (default 10000 ms) to each `send()` request only; its rejection message SHALL name the expected `${visualizerName}/` prefix so a `title` mismatch is diagnosable (design D9)
- [x] 2.6 Add `destroy()` that removes the iframe, clears the loader, fails the handshake `Task`, and detaches the `message` listener exactly once. Matching `development`, it does **not** cancel already-posted deferred requests — those settle on their own `requestTimeout` deadline (the ported `DeferredRequest` has no cancellation method; see 2.2a)
