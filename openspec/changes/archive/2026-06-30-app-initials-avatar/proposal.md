## Why

When a user-created application has no custom icon, every app shows the same generic fallback SVG — making the catalog visually monotonous and hard to distinguish at a glance. Replacing the generic icon with a deterministic colored background and initials derived from the app name gives each app a unique, recognisable identity at zero cost to the user.

## What Changes

- A new `InitialsAvatar` component in `libs/chat-shared` renders a square badge with a deterministic background color and 1–2 initials derived from a display name.
- Initials are generated by: taking the first letter of each word up to two words (e.g. "My App" → "MA"); for single-word names, the first two characters are used (e.g. "Summarizer" → "SU"). All initials are uppercased.
- The background color is chosen deterministically from a fixed palette based on a hash of the display name so the same app always gets the same color.
- **`FallbackEntityIcon` (`libs/chat-shared/src/assets/fallback-entity-icon.svg`) is removed in all code paths.** Every place that previously rendered the generic SVG fallback now renders `InitialsAvatar` instead.
- `DeploymentIcon` in `libs/chat-shared` replaces the `FallbackEntityIcon` default fallback with `InitialsAvatar`; it accepts `initialsName?: string` and uses it (falling back to `""` which renders `"?"` initials) when no image is available.
- `buildDeploymentIcon` in `libs/conversation-input` removes the direct `FallbackEntityIcon` render path and always passes `displayName` as `initialsName` to `DeploymentIcon`.
- All call sites in `apps/chat/src/` and `libs/catalog/` that previously rendered `FallbackEntityIcon` now pass `displayName` so `InitialsAvatar` is shown.

## Capabilities

### New Capabilities

- `app-initials-avatar`: A reusable `InitialsAvatar` component and initials/color utilities in `libs/chat-shared`, plus integration into `DeploymentIcon` and all callsites that render user-created app icons without a custom image.

### Modified Capabilities

- `deployment-icon-tooltip`: `DeploymentIcon` interface gains an optional `initialsName` prop; `buildDeploymentIcon` forwards `displayName` to it. No spec-level behavior changes for existing tooltip logic.

## Impact

- `libs/chat-shared/src/assets/fallback-entity-icon.svg` — **deleted**.
- `libs/chat-shared/src/components/DeploymentIcon/` — `FallbackEntityIcon` import removed; new `initialsName?: string` prop; `InitialsAvatar` is the new default fallback.
- `libs/chat-shared/src/components/InitialsAvatar/` — new component (new files).
- `libs/chat-shared/src/utils/` — new `initials.ts` and `avatar-color.ts` utilities.
- `libs/conversation-input/src/utils/deployment.tsx` — `FallbackEntityIcon` import removed; `buildDeploymentIcon` always uses `DeploymentIcon` with `initialsName`.
- `libs/catalog/src/components/AppIdentity/` and `CardGrid/` — `FallbackEntityIcon` references removed; `displayName` forwarded.
- `apps/chat/src/` — any direct `FallbackEntityIcon` renders replaced with `InitialsAvatar` or routed through the updated `buildDeploymentIcon`.
- No backend changes, no API changes, no new environment variables.
