# Proposal

## Why

`apps/chat-api` pins `@epam/ai-dial-typescript-sdk` at `0.2.1`
(`apps/chat-api/package.json:135`). `0.3.1` is the current stable release: it
carries the last DIAL Core contract syncs, and change 02 needs its
`createAnalyticsSDK` client. This change moves the pin on its own, so the Analytics
integration later starts from a pin already verified against the BFF and does not
mix in a contract review.

## Problem

Between `0.2.1` and `0.3.1` the SDK synced `open_api_core.yaml` from ai-dial-core
several times (18 commits on `epam/ai-dial-typescript-sdk` `0.2.1...0.3.1`). The
BFF consumes the SDK in two ways: through `createSDK` in
`apps/chat-api/src/dial/dial-client.service.ts:61` (86 operation methods called),
and through `components`/`operations` type imports in 21 files under
`apps/chat-api/src`. A Core-contract change can break compilation, change what a
request sends, or add a field that a hand-written mapper drops without notice.

## Solution

Pin `0.3.1` exactly and refresh `package-lock.json` through npm. A pre-planning
dry run, recorded in `design.md` "Pre-planning evidence", found:

- **Compilation:** `tsc` over chat-api's app and spec sources against the
  unpacked `0.3.1` declarations reports **0 errors**. The baseline against
  `0.2.1` also reports 0.
- **Runtime:** every one of the 260 `createSDK` methods and 257 URL builders
  that `0.2.1` ships is byte-identical in `0.3.1`. Only six plugin methods
  (`getPlugin`, `savePlugin`, …) and the separate Analytics module are new.
  `openapi-fetch` stays at `^0.17.0`; the lockfile already resolves it to `0.17.0`.
- **Contract:** 13 core schemas and 2 of the used operations changed. None is a
  rename or removal that a BFF DTO depends on, so no BFF response shape changes.
  `design.md` records a per-field decision for each of them.

The dry run did not modify `node_modules`, so task 1 is still a real install
followed by a typecheck. If that run disagrees with the dry run, `tasks.md` is
revised from its result before any fix is written.

## What Changes

- `apps/chat-api/package.json`: `"@epam/ai-dial-typescript-sdk": "0.2.1"` →
  `"0.3.1"` (exact, as today). `package-lock.json` is regenerated by npm, and
  only the SDK's `apps/chat-api` dependency entry and its
  `node_modules/@epam/ai-dial-typescript-sdk` entry change.
- No source change in `apps/chat-api/src` is expected. If the install-and-typecheck
  spike finds an error, the fix keeps every BFF DTO and the OpenAPI contract
  unchanged.
- `libs/chat-api-client/README.md` "Known divergence" note: it says
  `@epam/ai-dial-typescript-sdk@0.1.1` does not type `resetsAt`. The SDK has
  typed `CostItemLimitStats.resetsAt` / `ItemLimitStats.resetsAt` since at least
  `0.2.1`, and still does in `0.3.1`. The note is corrected to describe the
  current state. The `as unknown as UserLimitStatsResponseDto` cast it mentions
  stays.
- `createAnalyticsSDK` and the `Analytics*` types stay unused (change 02).

## Non-goals

- Any change to BFF behaviour, DTOs, `libs/chat-api-client/openapi.json` or the
  generated client.
- Adopting the new SDK surface: plugin methods, the `fields` param on
  `listDeployments`, `BudgetStats.object`, `ResourceAuthSettings.discovery_url`.
  These are recorded as follow-ups or as ignored on purpose.
- DIAL Analytics integration (change 02).
- Removing existing `as unknown as …` casts the SDK types now make redundant.

## Alternatives considered

Pin `^0.3.1` instead of `0.3.1`: rejected, because the repo pins the SDK exactly
(the `0.2.0` → `0.2.1` bump, `573a1b11a`, did the same), and `0.4.0-dev.1` is
already published. Bumping together with change 02: rejected, because it would
put the contract review in the same diff as the Analytics feature.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

None. No requirement changes: the BFF sends the same requests and returns the
same responses. The change sets `skip_specs: true` in `.openspec.yaml`. The specs
that name a minimum SDK version stay true at `0.3.1`:
`openspec/specs/toolset-write-api/spec.md` requires `0.2.0-dev.23` or later, and
`openspec/specs/deployment-details-api/spec.md` requires `0.3.0-dev.3` or later.

## Impact

- **Code:** `apps/chat-api/package.json`, `package-lock.json`,
  `libs/chat-api-client/README.md` (a docs-only note).
- **APIs:** none. `npm run openapi && npm run openapi:check` must report no diff.
- **Libs:** no lib code changes. The edit to the `libs/chat-api-client` README is
  prose, and the generated client is not regenerated.
- **Docs:** no doc cites `0.2.1`. `README.md`, `apps/chat-api/README.md` and
  `docs/architecture.md` name the package without a version, so they stay as they
  are.
- **i18n:** no user-visible strings.
- **Rollback:** not breaking. To revert, restore `"0.2.1"` in
  `apps/chat-api/package.json` and run `npm install` again, or revert the commit.

## Acceptance criteria

- `apps/chat-api/package.json` declares `"@epam/ai-dial-typescript-sdk": "0.3.1"`,
  and `package-lock.json` resolves `node_modules/@epam/ai-dial-typescript-sdk`
  to `0.3.1` with `openapi-fetch` still at `0.17.0`.
- `npm exec -- nx run-many -t typecheck,build,test,lint -p chat-api --skip-nx-cache`
  passes. `typecheck` is the inferred `tsc --build` target, and it covers both
  `tsconfig.app.json` and `tsconfig.spec.json`.
- `npm run openapi && npm run openapi:check` leaves
  `libs/chat-api-client/openapi.json` unchanged.
- `npm run validate:docs` passes.
- `git diff` touches only the three files above, plus any type-only fix the spike
  justifies in `design.md`.
