## Why

Skills are already a first-class catalog entity — authoring, favorites, sharing, archive import — but there is no way to actually use one in a conversation: the skill details panel offers no "Use in chat", and the conversation input's Add menu has no Skills entry. The backend contract for *sending* a skill with a completion has landed upstream (DIAL Core PR #1956, merged 2026-09-11: each `custom_content.skills` entry is a `{ url }` object carrying the skill's resource path, and Core auto-shares the referenced skill to the per-request API key like an attachment), so this change builds both the frontend selection UX (catalog button, input menu, favorites panel, browse modal) **and** the send-time/history wiring behind a deployment-controlled kill switch. Part 2 of the effort (originally deferred) is folded in: the selected skill renders as an inline `ChatSkill` element *inside* the conversation input (not as a chip outside it), a `/`-prefix command dropdown offers the same favorites panel from the keyboard, sent messages carry the skill path, and the conversation history renders the skill with the same interactive tooltip and details action.

## What Changes

- **Feature flag `SKILL_USAGE_ENABLED`** — new boolean env var validated at boot (`apps/chat-api/src/config/environment.config.ts`), exposed to the frontend as the client-visible `features.skillUsageEnabled` config-registry entry (mirroring how `RESPONSES_API_ENABLED` becomes `features.responsesApiEnabled`, except client-visible because it gates UI). Every piece of skill-usage UI below renders only when the flag is true. Documented in `.env.template` and `apps/chat-api/README.md`.
- **"Use in chat" on the skill details panel** (`libs/catalog` `DetailsPanel`/`Header`) — for `CatalogEntityType.Skill`, the header gains the "Use in chat" primary action (displacing Download, which returns to the Manage menu). Clicking it navigates to the chat route and attaches the skill to the conversation input, mirroring the prompt flow (router state, one-shot). **Deferred condition, documented in specs/design:** the button should eventually render only when the default model supports skills — the backend exposes no way to know that yet, so it is shown unconditionally (within the flag) for now.
- **"Skills" item in the conversation input Add menu** — new menu item (icon `IconBlocks`) rendered only under the flag, using the same nested-flyout (desktop) / stacked-bottom-sheet (mobile) chrome the Prompts item gets. Its panel contains: "My Collection" header, the user's favorite skills, a separator, and a "Browse" button; with no favorites it shows "Star a skill to pin it here".
- **Interactive tooltip on favorite-skill rows + chat-route skill details side panel** — each favorite row is wrapped in the ui-kit's `InteractiveTooltip` (shipped in 0.14): a panel anchored to the row (Right placement, 550px max width on desktop) that stays open while the pointer moves onto it, showing the skill's description above a link-style "View details" button (`IconEye` on its inline-start). Descriptions are not in the listing response Core sends today, so they are lazy-fetched: the first open of a row's tooltip (hover or focus) triggers one `SKILL.md` download + manifest parse, cached per session; until resolved — or when a manifest has no description — the panel shows the button alone. "View details" opens the catalog's skill details side panel on the chat route, composed from `DetailsPanel` newly exported by `libs/catalog`, with favorite toggle and "Use in chat" wired; on touch-only devices the tooltip renders nothing (rows still select on tap).
- **"Use skill" browse popup** — "Browse" opens the standard catalog picker shell (`CatalogView` in selector mode) restricted to the Skills tab only, mirroring the "Use prompt" modal.
- **New `ChatSkill` inline component (`libs/skills`)** — a `GhostButton` labeled `/{skill name}` (e.g. `/my-skill`) wrapped in the ui-kit `InteractiveTooltip`. Its tooltip is the *same* panel the Add-menu favorite rows show — the shared tooltip content (description with loading spinner + "View details" link button with `IconEye`) is extracted so the menu rows, the input chip, and history all render it identically, i18n included. Activating the button does nothing except open the tooltip (hover and focus do the same); "View details" invokes the host callback, which opens the catalog skill details side panel exactly as it does from the menu. Accepts skill metadata (name, description, path) plus the callback.
- **Selected skill rendered inline inside the input** — a skill picked from any entry point becomes the single selected skill, rendered *inside* the conversation input's text area at its inline-start as a `ChatSkill` element; the user can keep typing in the same input and the text flows around the element (first line starts after it, wrapped lines use the full width — the Claude/other-chat-agents composer pattern). `libs/conversation-input` gains a generic `inlineStartSlot: ReactNode` prop driving the flow-around mechanics; it stays domain-agnostic (the app passes `<ChatSkill />`). The part-1 `selectedEntities` chip row and `SelectedEntityChips` component are removed in the same change — the selected skill was their only consumer. The chip carries no remove control of its own — removal is the input's Backspace-at-position-0 gesture (design D11, resolving the earlier recorded assumption).
- **Slash `/` command dropdown** — when the input text is empty and the user types `/`, a dropdown opens above the input anchored to the text area. Its content is the same favorites panel the Skills submenu shows ("My Collection" header, favorite rows, Browse footer), with the characters typed after the `/` filtering the rows (matched text highlighted with the shared `Highlight` component). Picking a row consumes the `/query` text from the input (it is removed, not sent) and selects the skill. Deleting the `/` closes the dropdown; if the user dismisses it (Escape / outside click), it stays closed until the `/` is deleted and typed again. The Add-menu "Skills" item is unchanged and remains available.
- **Send-time wiring: `custom_content.skills`** — `MessageCustomContent` gains `skills?: RequestSkill[]` (each entry `{ url }` — the skill's resource path in the same URL form as the listing/CatalogItem id — matching DIAL Core's merged `RequestSkill` schema, PR #1956; a bare-string entry is rejected by Core with 400). Sending a message with a selected skill attaches the path to the user message and clears the selection (per-message semantics, like attachments); regenerate/continue flows forward the stored payload unchanged; editing a message restores its skill into the input. No new endpoints — the field rides the existing message `custom_content` channel (attachments/stages use it today).
- **Skill in conversation history** — a user message that carries `custom_content.skills` renders the `ChatSkill` element with the message (inline-start of the bubble content). Hovering it shows the same interactive tooltip, and "View details" opens the skill details side panel. Skill metadata (name, description) is resolved from the path: the loaded skill listing when it contains the path, a path-segment fallback name otherwise, and the existing per-session lazy description fetch for descriptions.
- **Refactor: reusable menu-overlay plumbing in `libs/conversation-input`** — the prompt-specific `promptsMenuOverlay`/`promptsMenuTitle`/`promptsBackLabel` props on `Input`/`ConversationInput`/`AddAttachmentButton` are generalized into a data-driven overlay-menu mechanism that any catalog-entity-type submenu can use; Prompts migrates onto it with no behavior change, Skills consumes it as the second client.
- **New `libs/skills` library** (`@epam/ai-dial-skills`) — hosts the host-agnostic skill-selection UI: the favorite-skills panel (rows wrapped in the ui-kit `InteractiveTooltip`), the `SkillDetailsSidePanel` wrapper composing `libs/catalog`'s exported `DetailsPanel`, and skill-specific models/types. App-owned wiring (contexts, i18n, navigation, the lazy description fetch) stays in `apps/chat` via a `useSkillSelectorOverlay` hook mirroring `usePromptSelectorOverlay`.

## Capabilities

### New Capabilities
- `skill-input-attachment`: Discovering, selecting, and displaying a skill from the conversation input — the Skills Add-menu item and flag gate, the favorites panel (rows with the interactive tooltip and lazy-fetched descriptions), the Skills-only browse modal, the `/`-prefix command dropdown reusing the same panel content, the `ChatSkill` inline element rendering the single selected skill inside the input with the text flowing around it, and the chat-route skill details side panel the tooltip's "View details" opens — plus the shared menu-overlay mechanism in `libs/conversation-input` both Prompts and Skills use.
- `skill-message-payload`: Carrying a used skill on the conversation wire — the `custom_content.skills` field on user messages (`{ url }` entries per Core's merged `RequestSkill` schema, PR #1956; send-time construction, per-message clearing on send, persistence, regenerate/continue forwarding, edit restore), rendering the skill in the conversation history with the same interactive tooltip and "View details" action, and resolving skill metadata (name, description) from the carried urls.

### Modified Capabilities
- `catalog-use-in-chat`: gains a `CatalogEntityType.Skill` branch — "Use in chat" on a skill navigates to the chat route and attaches the skill to the composer via one-shot router state, without touching deployment selection; the skill details panel header offers the action (flag-gated, currently unconditional — the default-model-supports-skills condition is deferred and documented).
- `chat-input-tools-menu`: the "no `+` button when tools are the menu's only content" requirement's enumeration gains the skills overlay alongside attachments, chat settings, and prompts.
- `config-registry-and-env-provider`: the registry gains the `features.skillUsageEnabled` entry — `type='feature'`, `valueType='boolean'`, `visibility='client'`, `defaultValue=false`, `critical=false`, `envVar='SKILL_USAGE_ENABLED'`.
- `skill-details-panel`: `DetailsPanel` is exported from `@epam/ai-dial-catalog`'s index and becomes composable outside the Catalog page (the chat-route side panel is its second consumer; the details-resolution pipeline itself is unchanged).

## Impact

- **apps/chat-api**: `environment.config.ts` (`SKILL_USAGE_ENABLED`, boolean transform identical to `RESPONSES_API_ENABLED`), `config-registry.constants.ts` (new entry), `feature-key.enum.ts` (`FeatureKey.SkillUsageEnabled`), `.env.template`, `apps/chat-api/README.md` env-var table. No new endpoints.
- **libs/conversation-input**: `AddAttachmentButton`/`Input`/`ConversationInput` props change (`promptsMenuOverlay` family → generic overlay-menu config); `Input`/`ConversationInput`/`EditMessageInput` additionally gain the generic `inlineStartSlot` prop (flow-around inline content in the text area) and the generic slash-command-menu mechanism, and lose the part-1 `selectedEntities`/`selectedEntityChipLabels` props (the `SelectedEntityChips` component is removed — the selected skill was their only consumer); `apps/chat` call sites updated in the same change; existing Prompt menu behavior and tests preserved.
- **libs/conversation-messages**: `UserMessageBubble` (via `MessageBubble`) gains a `beforeContent` slot so the host can render the `ChatSkill` element at the inline-start of a user message's content; no behavior change for existing consumers.
- **libs/chat-shared**: `MessageCustomContent` gains the optional `skills?: RequestSkill[]` field and the `RequestSkill` model (`{ url }` entries per Core's merged contract, PR #1956) — the wire channel attachments/stages already use.
- **libs/catalog**: `Header` — Skill gains the primary action (host-gated via `isPrimaryActionVisible`/`onUseInChat`, so the lib stays flag-agnostic). `DetailsPanel` becomes a public export of the lib's index (composed by `libs/skills`' `SkillDetailsSidePanel` for the chat-route side panel); its README gains the new export.
- **New libs/skills**: `FavoriteSkillsPanel` (rows with `InteractiveTooltip`, plus the optional slash-filter mode), the extracted shared tooltip content used by rows/`ChatSkill`/history, the new `ChatSkill` inline component, `SkillDetailsSidePanel`, and `FavoriteSkillItem` models; peers on `@epam/ai-dial-ui-kit`, `@epam/ai-dial-chat-shared`, and `@epam/ai-dial-catalog`. Requires `docs/architecture.md`, root/app README, and `validate:docs` updates.
- **apps/chat**: `useSkillSelectorOverlay` (mirrors `usePromptSelectorOverlay`; grows the slash-menu wiring, send-time `custom_content.skills` construction, and path→metadata resolution for history), "Use skill" catalog modal (mirrors `PromptCatalogModal`), `CatalogView` header-rule wiring for Skill, `ConversationRoute` consumption of one-shot skill router state, edit-flow skill restore, new `SkillSelectorI18nKeys` + `en.json` keys (reusing `ButtonsI18nKeys` for shared labels).
- **Out of scope**: DIAL Core's *interpretation* of `custom_content.skills` — shipped upstream (PR #1956, merged 2026-09-11: entry validation, per-request auto-share of referenced skills like attachments); this repo only constructs, persists, and re-displays the payload in the merged `{ url }` shape. Displaying `skills` on *assistant* messages — Core's merged contract defines the field on assistant message custom content as well ("skills referenced by the model as part of the response"); the shared `MessageCustomContent` type covers both roles, but history rendering of assistant-referenced skills is a recorded follow-up; adding `description` to DIAL Core's skill metadata listing (planned upstream change — until it ships, descriptions are lazy-fetched per skill from `SKILL.md` via the existing skill-file download endpoint; when it lands, the lazy fetch and its N+1 request pattern are dropped — see Follow-ups in `design.md`); ui-kit Dropdown-native interactive tooltips (shipped upstream — the upgraded kit fixed the `InteractiveTooltip` `onOpenChange` and submenu-close defects, and the panel-controlled open + grace-close workaround in the favorites panels has been dropped; see Follow-ups in `design.md`); any new backend skill-usage API, endpoint, or OpenAPI change; role-based rollout env var for the flag. The Prompts favorites rows were originally deferred to a follow-up change but were migrated onto `InteractiveTooltip` (same row-tooltip behavior as skills, description already available so no lazy fetch) within this change at the maintainer's request. The originally-deferred "part two" (send-time semantics, persistence, history display) is now **in scope** — the send-time semantics bullet above and the `skill-message-payload` capability cover it.
