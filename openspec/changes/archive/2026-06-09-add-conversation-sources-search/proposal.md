## Why

The `ConversationSourcesPanel` surfaces all attachments from a conversation (uploaded by the user and generated by the assistant), but provides no way to locate a specific file when the list grows long. Adding a search input lets users quickly filter files by name across both sections.

## What Changes

- Add a `SearchInput` to the `ConversationSourcesPanel` header area, using the existing `libs/sidebar/src/components/SearchInput/SearchInput.tsx` component.
- Filter both `uploaded` and `generated` attachment arrays by the current search query (case-insensitive match on display name / title).
- When a search query is active and no attachments match, show a "No results found" empty state instead of the default "No data" state.
- When no query is entered, no filtering is applied and all attachments render as before.

## Capabilities

### New Capabilities

- `conversation-sources-search`: Text search within the ConversationSourcesPanel that filters uploaded and generated attachments by name; shows "No results found" when the filtered result is empty.

### Modified Capabilities

<!-- none -->

## Impact

- `apps/chat/src/components/ConversationSourcesPanel/ConversationSourcesPanel.tsx` — add local search state and pass filtered arrays to `FilesSection`.
- `apps/chat/src/components/ConversationSourcesPanel/` — no new files needed; the search state is local to the panel component.
- `libs/sidebar/src/components/SearchInput/SearchInput.tsx` — consumed as-is; no changes to the lib.
- i18n: new translation keys for the search placeholder and "No results found" label.
