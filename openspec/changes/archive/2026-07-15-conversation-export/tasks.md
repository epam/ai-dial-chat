- [x] 4.3 **Bug fix from live testing:** exporting a real conversation returned `400 Bad Request` from DIAL Core. Root cause: `getConversation` was called with the raw `ConversationListItemDto.id` (`conversations/{bucket}/{name}`), but the backend's `resolveConversationLocation` expects `{bucket}/{name}` (no `conversations/` prefix) and naively slash-splits the value, so the un-stripped id made it treat the literal word `"conversations"` as the bucket. Added regression tests in `useConversationExport.spec.ts` using realistic `conversations/{bucket}/{name}`-shaped ids (the original tests used bare `'conv-1'` ids that could never have caught this).
