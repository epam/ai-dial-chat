# Tasks

Slicing strategy: **risk-first, then vertical.** Group 1 pins the load-bearing assumptions (Core accepts the staging path and dot-folder namespace; the status mapping works) with evidence from code and tests, before anything is built on them. No task calls a live DIAL Core. Groups 2–4 then deliver one path through the backend end to end. Group 5 is the panel text and group 6 is the closing check. Each group lands its own tests and docs. Backend work follows `apps/chat-api/AGENTS.md`; relative imports are extensionless. Run `npm run verify:changed` once after each completed group and `npm run verify:full` once at the end.

Known limitations are recorded in `proposal.md` and `design.md` D8/D11; no task adds a guard for them.
